# 신규 제보 승인 전 개방시간 검토

신규 제보의 개방시간·상세 텍스트 편집란을 없애고 `개방시간 검토`와 같은 공통 양식을 사용한다. 기존 시설의 개방시간 조치에도 같은 양식을 적용한다.

- 운영 정책, 24시간 여부, 공휴일 정책과 월~일 시간표를 한곳에서 편집한다.
- 한 요일의 여러 시간대, 휴무, 익일 종료를 보존한다. 선택하지 않은 요일은 미확인이며 임의로 휴무 처리하지 않는다.
- 사용자 문구는 제보 원문에 남긴다. 승인 요청은 기존 `confirmedFacilityInfo.openingHours` 계약을 사용한다. 자유 문구를 자동으로 시간표로 추정하지 않는다.
- 신규 제보에서 정책이 미확인이면 정형 시간표는 null로 유지한다. 요일별 정책의 빈 시간표·누락/동일 시작·종료 시각은 승인 요청 전에 차단한다.
- 기존 정형 시간표의 복수 시간대가 검토 양식을 다시 열 때 누락되지 않는다.

## 검증과 적용 상태

제보·개방시간 회귀 검사와 실데이터 프리뷰에서 신규 대기 제보의 요일별 입력, 시간대 추가·삭제, 익일 종료, 공휴일 변경을 확인했다. 승인 요청에 정형 값과 원문이 함께 전달되는지는 자동 검사로 검증했다.

프리뷰: https://preview.geupddong.com/admin-hours-review/reports.html

프리뷰는 기존 관리자 인증으로 실제 데이터를 조회하며 운영 쓰기는 기존 프리뷰 보호 기능으로 차단한다. 새 양식으로 운영 제보를 실제 승인하거나 시설을 변경하지 않았다. API·DB 스키마·캐시 정책 변경은 없다. 사용자가 프리뷰를 검수하고 운영 반영을 승인했다. 실제 배포 상태는 관련 WBS와 PR의 CI/CD 실행에서 확인한다.

관련 WBS: https://github.com/toilet-project/toilet-web/issues/370
