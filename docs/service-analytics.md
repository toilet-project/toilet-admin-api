# 서비스 이용 분석

관리자 홈과 `서비스 이용 분석` 상세 화면은 급똥 API가 직접 수집한 최소 이벤트와 일별 집계만 조회한다. Google 태그, Google Analytics Data API, 속성 ID, 서비스 계정 파일은 사용하지 않는다.

API의 `V21__replace_ga_snapshot_with_service_analytics.sql`이 원본 이벤트, 일별 요약, 일별 차원, 배치 실행 이력 테이블을 만든다. 웹은 원문 검색어·회원 식별값·정확한 좌표·주소·자유 입력을 보내지 않는다. API는 접속망 일부와 기기 정보를 기간별 HMAC으로 바꾸고 원본 IP를 분석 테이블에 저장하지 않는다.

오늘 데이터는 5분 간격으로 갱신한다. 매일 한국시간 02:30에 직전 14일을 다시 집계해 지연 도착 이벤트를 보정하며, 개별 이벤트는 35일 뒤 삭제한다. 일별 집계는 장기 추이에 사용한다.

배포 순서는 관리자 화면을 먼저 반영해 저장소 준비 상태를 안전하게 표시하고, 다음으로 API 스키마와 수집기를 준비한 뒤 마지막에 웹 수집기를 연결하는 방식으로 진행한다. WEB 배포 전에는 실행 중인 캐시 예열 작업을 확인하고 별도 승인을 받는다.

## 봇 접근 내역

`봇 접근` 탭은 사람의 방문 통계와 별개로 **미니 PC Nginx에 도착한 요청**만 보여준다. Googlebot·Naver Yeti·Bingbot의 공식 IP 확인, 이름만 확인, 공식 IP 불일치를 구분하고 기간·봇 이름·상태별 요청 수, 시간대, 최초/마지막 접근, 경로 유형, 4xx·5xx를 조회한다.

Cloudflare 차단 요청이나 CDN에서 끝난 요청은 포함하지 않는다. 수집기 미연결·지연·부분 기록을 0건으로 취급하지 않는다. 이름을 숨긴 모든 봇을 탐지하거나 실제 검색 색인을 증명하는 기능은 아니다. 과거 출처 없는 방문 전체를 삭제하지 않고, 서버 요청 수를 방문자 수에서 차감하지 않는다.

IP·UA·원문 URL은 로그 판별 중에만 사용하고 새 분석 저장소에는 남기지 않는다. 전용 수집기 SQLite의 35일 집계를 읽기 전용 JSON으로 연결한다. 수집기는 약 1분마다 갱신하며 운영 설치/연결은 [수집기 및 적용 순서](../operations/origin-bots/README.md)를 따른다. 최초 연결 직후는 과거 전 기간의 완전한 통계가 아니므로 부분 기록 안내를 유지한다.

## 날짜 행의 봇 제외 토글

날짜 필터 오른쪽의 `봇 제외`는 기본 켜짐이다. 끄면 **분석 이벤트 저장소에 보관된 봇 이벤트**를 포함한다. 요약·이전 기간·시간대·유입·페이지·이용 흐름·실시간·CSV에 동일하게 적용하며, 조회 실패 시 토글과 숫자를 마지막 성공 조건으로 함께 되돌린다. `봇 접근` 탭에는 적용하지 않는다. 그 탭은 방문 이벤트가 아닌 Nginx 요청을 분석하기 때문이다.

- 수집 API는 요청의 자동화 신호를 `BOT` 또는 `UNFLAGGED`로 표시한다. 미탐지 상태는 사람임을 뜻하지 않고, 봇 표시는 공식 IP 검증과도 다르다. 원문 IP·UA는 추가 저장하지 않는다.
- 분류 전 기록은 `LEGACY`로 보존한다. 재판별 근거가 없으므로 직접 접속 전체를 봇으로 바꾸거나 삭제하지 않는다. 과거 기록만 있는 프리뷰에서는 토글을 바꿔도 수치가 같다는 안내를 표시한다.
- 일별 장기 집계는 봇 제외 기준을 유지한다. 봇 포함 조회는 원본 이벤트 보관 기간인 최근 35일 이내에만 제공한다. 봇 이벤트도 동일하게 35일 뒤 정리한다.
- 이미 수집 단계에서 버린 봇 이벤트는 복원하지 않는다. 서버 봇 요청 수를 방문자·페이지뷰에서 빼지 않는다.

### 운영 적용 순서

1. 관리자 조회·기본 봇 제외 기능을 먼저 배포한다. 분류 컬럼이 없는 기존 DB도 읽을 수 있다.
2. API의 `V33__classify_service_analytics_traffic.sql`과 수집 코드 배포를 진행한다. 병합 전 다른 작업의 마이그레이션 번호와 충돌 여부를 다시 확인한다.
3. 관리자·배치·실시간 제외 검증 후 `SERVICE_ANALYTICS_RETAIN_BOT_EVENTS=true`로 보관을 켠다. 기본값은 꺼짐이라 이전 관리자에 봇이 섞이지 않는다.
4. 롤백 때는 보관 설정부터 끈다. 기록을 삭제하지 않으며, 보관된 봇을 제외하지 못하는 이전 관리자 버전으로 되돌리지 않는다.

프리뷰는 읽기 전용 복사본이므로 수집 시점 이후 기록이 자동으로 반영되지 않는다. 실제 운영 적용 여부와 남은 연결 작업은 [WBS의 현재 상태](https://github.com/toilet-project/toilet-admin-api/issues/120)에서 확인한다. 분석 이벤트 분류와 별도의 Nginx 수집기 설치를 구분하여 기록한다.
