# 서비스 이용 분석

관리자 홈과 `서비스 이용 분석` 상세 화면은 급똥 API가 직접 수집한 최소 이벤트와 일별 집계만 조회한다. Google 태그, Google Analytics Data API, 속성 ID, 서비스 계정 파일은 사용하지 않는다.

API의 `V21__replace_ga_snapshot_with_service_analytics.sql`이 원본 이벤트, 일별 요약, 일별 차원, 배치 실행 이력 테이블을 만든다. 웹은 원문 검색어·회원 식별값·정확한 좌표·주소·자유 입력을 보내지 않는다. API는 접속망 일부와 기기 정보를 기간별 HMAC으로 바꾸고 원본 IP를 분석 테이블에 저장하지 않는다.

오늘 데이터는 5분 간격으로 갱신한다. 매일 한국시간 02:30에 직전 14일을 다시 집계해 지연 도착 이벤트를 보정하며, 개별 이벤트는 35일 뒤 삭제한다. 일별 집계는 장기 추이에 사용한다.

배포 순서는 관리자 화면을 먼저 반영해 저장소 준비 상태를 안전하게 표시하고, 다음으로 API 스키마와 수집기를 준비한 뒤 마지막에 웹 수집기를 연결하는 방식으로 진행한다. WEB 배포 전에는 실행 중인 캐시 예열 작업을 확인하고 별도 승인을 받는다.

## 봇 접근 내역

`봇 접근` 탭은 사람의 방문 통계와 별개로 **미니 PC Nginx에 도착한 요청**만 보여준다. Googlebot·Naver Yeti·Bingbot·Applebot의 공식 IP 확인, 이름만 확인, 공식 IP 불일치를 구분하고 기간·봇 이름·상태별 요청 수, 시간대, 최초/마지막 접근, 경로 유형, 4xx·5xx를 조회한다. AhrefsBot·AhrefsSiteAudit도 이름별로 표시하며 공식 인증을 뜻하지 않는 `이름만 확인` 상태다. 과거 Other bot은 최근 35일의 보존 로그와 기존 집계가 정확히 일치하는 구간에서만 Ahrefs 이름으로 분리할 수 있다. 요청 수와 오류 건수는 유지하고 원본 없는 구간·미확인 봇은 그대로 남긴다. 구현 준비와 운영 반영은 별개다.

Cloudflare 차단 요청이나 CDN에서 끝난 요청은 포함하지 않는다. 수집기 미연결·지연·부분 기록을 0건으로 취급하지 않는다. 이름을 숨긴 모든 봇을 탐지하거나 실제 검색 색인을 증명하는 기능은 아니다. 과거 출처 없는 방문 전체를 삭제하지 않고, 서버 요청 수를 방문자 수에서 차감하지 않는다.

IP·UA·원문 URL은 로그 판별 중에만 사용하고 새 분석 저장소에는 남기지 않는다. 전용 수집기 SQLite의 35일 집계를 읽기 전용 JSON으로 연결한다. 수집기는 약 1분마다 갱신하며 운영 설치/연결은 [수집기 및 적용 순서](../operations/origin-bots/README.md)를 따른다. 최초 연결 직후는 과거 전 기간의 완전한 통계가 아니므로 부분 기록 안내를 유지한다.

### 통계에서 분리한 자동화

`봇 접근`의 상단은 별도 `automation-statistics.json`을 읽어 분석 이벤트의 `UA_SIGNAL`(요청 자동화 표시)과 `PATTERN_INFERRED`(반복 행동 패턴으로 판별)를 구분한다. 후자는 `DISTRIBUTED_PASSIVE_PROFILE`, `KNOWN_BULK_CLIENT`의 확인 근거를 표시하며 운영 주체의 신원을 확인했다는 뜻은 아니다. 하단의 공식 IP 확인·이름만 확인·IP 불일치는 계속 Nginx **서버 요청** 지표다. 두 영역을 합치거나 서버 요청을 방문 통계에서 빼지 않는다.

분류 작업의 집계는 기존 읽기 전용 마운트 `/var/lib/geupddong-origin-bots` 아래 새 파일만 사용한다. 기존 `origin-bots.json` 형식·수집기는 변경하지 않는다. 관리자 `GET /api/admin/v1/service-analytics/automation-statistics`는 선택 날짜의 일별 합계와 작업 주기·마지막 완료·전체 대조 범위를 반환한다. 독립 서비스는 DB·원본 로그·복구 원장을 읽거나 쓰지 않으며 고정 파일명·크기 제한·값 허용 목록으로 원문 IP·UA·해시·임의 오류 문구를 응답에서 배제한다.

`plan`은 분리 예정치이고 운영 미반영, `ready`는 현재 기간의 원장 소유 분류 합계다. `partial`·`error`·15분 이상 갱신 지연은 완료·0건으로 취급하지 않는다. 작업 대조 범위는 화면 날짜 범위와 다를 수 있어 둘 다 표시한다. 일반 통계는 기존 기본 봇 제외 조건을 사용한다. 이 기능은 통계 분류용이며 접속·검색·OAuth·보안 규칙·차단 설정을 변경하지 않는다. 운영 적용·되돌리기는 분류 작업과 그 복구 원장이 담당하며 이 조회 화면에는 쓰기 기능이 없다.

`공개 IP 대조 범위 · 전체 봇 목록 아님`에는 8개 제공처의 19개 공식 공개 출처 URL을 표시한다. 전체 봇 목록이나 완전한 신원 명부가 아니다. 실제 조회 메타데이터가 없으면 ‘미보고’로 남기고 대조 완료 시각·대역 개수를 만들지 않는다. 선택적으로 같은 읽기 전용 디렉터리에 `official-crawler-sources.json` (`schema:1`, `source:"official-crawler-source-catalog"`, `officialSources` 메타데이터)을 두거나 작업 내보내기에 `officialSources`를 포함할 수 있다. 원본 IP 대역은 이 메타데이터에 필요하지 않다. 목록에 없다는 사실만으로 악의나 자동화를 판정하지 않는다.

## 날짜 행의 봇 제외 토글

날짜 필터 오른쪽의 `봇 제외`는 기본 켜짐이다. 끄면 **분석 이벤트 저장소에 보관된 봇 이벤트**를 포함한다. 요약·이전 기간·시간대·유입·페이지·이용 흐름·실시간·CSV에 동일하게 적용하며, 조회 실패 시 토글과 숫자를 마지막 성공 조건으로 함께 되돌린다. `봇 접근` 탭에는 적용하지 않는다. 그 탭은 방문 이벤트가 아닌 Nginx 요청을 분석하기 때문이다.

- 수집 API는 요청의 자동화 신호를 `BOT` 또는 `UNFLAGGED`로 표시한다. 미탐지 상태는 사람임을 뜻하지 않고, 봇 표시는 공식 IP 검증과도 다르다. 원문 IP·UA는 추가 저장하지 않는다.
- 분류 전 기록은 `LEGACY`로 보존한다. 재판별 근거가 없으므로 직접 접속 전체를 봇으로 바꾸거나 삭제하지 않는다. 과거 기록만 있는 프리뷰에서는 토글을 바꿔도 수치가 같다는 안내를 표시한다.
- 일별 장기 집계는 봇 제외 기준을 유지한다. 봇 포함 조회는 원본 이벤트 보관 기간인 최근 35일 이내에만 제공한다. 봇 이벤트도 동일하게 35일 뒤 정리한다.
- 이미 수집 단계에서 버린 봇 이벤트는 복원하지 않는다. 서버 봇 요청 수를 방문자·페이지뷰에서 빼지 않는다.

### 운영 적용 순서

1. 관리자 조회·기본 봇 제외 기능을 먼저 배포한다. 분류 컬럼이 없는 기존 DB도 읽을 수 있다.
2. API의 `V33__classify_service_analytics_traffic.sql`과 수집 코드 배포를 진행한다. 병합 전 다른 작업의 마이그레이션 번호와 충돌 여부를 다시 확인한다.
3. 관리자·배치·실시간 제외 검증 후 `SERVICE_ANALYTICS_RETAIN_BOT_EVENTS=true`로 보관을 켠다. 기본값은 꺼짐이라 이전 관리자에 봇이 섞이지 않는다.
4. 롤백 때는 보관 설정부터 끈다. 기록을 삭제하지 않으며, 보관된 봇을 제외하지 못하는 이전 관리자 버전으로 되돌리지 않는다.

프리뷰는 읽기 전용 복사본이므로 수집 시점 이후 기록이 자동으로 반영되지 않는다. 실제 운영 적용 여부와 남은 연결 작업은 [WBS의 현재 상태](https://github.com/toilet-project/toilet-admin-api/issues/120)에서 확인한다. 분석 이벤트 분류와 별도의 Nginx 수집기 설치를 구분하여 기록한다.

## 세션별 접속 단서 분류

유입 화면의 단서 표는 최근 35일의 **선택 조건 안에서 시작 기록이 있는 모든 세션**을 대상으로 한다. 각 날짜·세션의 첫 시작 기록을 기준으로 삼고, 중복 시작은 세션 수를 늘리지 않는다. 세션별 조회·기능 이벤트·활성 시간을 먼저 계산한 뒤 같은 환경·경로 유형·관찰 분류끼리 묶는다. 행 평균으로 개별 세션의 행동을 추정하지 않는다. 날짜가 바뀐 뒤 시작 기록 없이 남은 이벤트도 포함해, 시작 기록 없는 이벤트 수를 별도로 표시한다.

API의 기존 `entryClues.rows`·`truncated`는 출처 미확인 세션만 묶던 7개 환경 차원과 상위 100개 제한을 그대로 유지한다. 신규 전체 세션 분류는 추가 필드 `entryClues.review.rows`·`review.truncated`와 전체 합계에 제공한다. 두 목록의 제한은 독립적이다. 이미 열린 이전 화면이 기존 목록을 계속 읽어도 확인된 유입이 섞이지 않는다. 새 화면이 이전 API에 연결되면 기존 출처 미확인 표로 되돌리고, 환경 선택도 출처 미확인 조건을 유지한다.

다음 우선순위로 한 세션에 한 분류를 부여한다. 기존 `traffic_class`를 수정하거나 자동으로 차단·제외하지 않으며, 현재 봇 제외 토글과 필터를 그대로 따른다.

1. 과거 미분류 또는 서로 다른 기존 트래픽 표시가 섞임: 판단 보류.
2. 기존 `BOT`: 자동화 신호 표시. 공식 봇 신원 인증을 뜻하지 않는다.
3. 페이지 조회 기록이 없음: 기능 이벤트가 있더라도 페이지 조회 누락을 우선 표시한다. 시작 이벤트만 있다는 뜻은 아니다.
4. 시작·페이지 조회·활성 시간 이외의 이벤트가 있음: 기능 이용 기록. 사람임을 보증하지 않는다.
5. 요청 또는 로그로 앱 환경이 확인됨: 앱 환경 단서.
6. 새로고침·뒤로가기·열린 탭 세션 재시작: 재진입 단서.
7. 출처 없음(`Direct/none`, `Unassigned/unknown` 조합)이며 조회가 정확히 한 번: 활성 시간 0과 양수를 각각 구분한다. 자동화 의심 후보를 검토할 단서이며 봇 확정이 아니다.
8. 그 밖에 활성 시간이 있으면 화면 활성 기록, 나머지는 미확정으로 유지한다.

합계는 상위 100개 유형 제한 **이전**에 계산해 전체 시작 세션과 일치시킨다. 표에는 반환된 유형이 포함하는 세션 수·비율을 표시한다. 표의 분류 선택·검색과 해당 CSV 행에는 반환된 상위 유형만 적용된다. 빈 검색 결과를 그 분류의 전체 0건으로 해석하지 않는다. 더 좁은 기간·환경 필터로 나머지 유형을 확인할 수 있다. 환경 버튼은 같은 환경·출처의 분석을 열며 관찰 분류 자체를 다른 그래프에 적용하는 필터는 아니다.

CSV에는 전체 분류 합계, 표 포함 범위, 표 필터·검색 조건과 반환된 유형의 기존 트래픽 표시·관찰 분류를 함께 쓴다. 원본 IP·UA·세션 해시나 실제 상세 URL은 반환하지 않는다. 첫 화면은 익명화한 경로 유형이므로 같은 화장실 URL을 반복 조회했다는 근거로 쓸 수 없다. 운영 배포 전 코드와 검증을 완료한 상태와 실제 운영 반영 여부는 구분한다.

## 화면별 상세 조회와 비용 검증

`GET /api/admin/v1/service-analytics/explore`의 선택 매개변수 `view`는 `overview`, `quality`, `content`, `acquisition`, `behavior`, `audience`, `all`을 받는다. 생략하면 기존과 같은 전체 조회(`all`)를 제공한다. 알 수 없는 값은 DB 조회 전에 400으로 거절한다.

모든 화면은 공통 필터 목록에 필요한 페이지·유입 소스·국가·접속 환경을 조회한다. 페이지·화면은 화면 유형, 유입 경로는 채널·확인 근거·진입 방식과 세션별 접속 단서, 이용 행동은 이벤트·이용 흐름, 방문 환경은 기기·운영체제·브라우저·도시를 추가한다.

실시간 API는 실시간 패널이 있는 요약 화면을 조회할 때만 호출한다. 다른 분석 탭의 추가 조회로 실시간 집계를 반복하지 않는다. 처음 여는 탭은 추가 API 응답을 기다리므로 초기 조회 비용과 전체 탭의 탐색 비용을 구분해 확인한다.

같은 기간·필터·봇 제외 조건은 기존의 최대 32개·60초 캐시 안에서 이미 조회한 항목을 재사용한다. 추가 탭 조회는 누락된 항목만 순차 집계하며, 최초 조회의 기준 시각과 비교 기간을 유지한다. 추가 집계는 캐시 만료를 연장하지 않는다. 응답은 이미 조회한 항목을 함께 포함할 수 있다. 실패한 추가 조회는 마지막 성공 캐시를 바꾸지 않으며, UI는 마지막 성공 화면·조건으로 복구한다. 원본 이벤트·일별 집계·보관 기간·권한·DB 인덱스는 변경하지 않는다.

### 합성 SQL 비교

`AnalyticsExploreCostTest`는 고정 시각과 동일한 합성 이벤트를 사용해 기존 전체 조회와 화면별 조회의 **실제 원본 집계 SQL 실행 횟수** 및 결과 동등성을 검증한다. 메타데이터 확인·최초 이벤트일·최종 갱신 시각 조회와 별도 실시간 API는 아래 횟수에서 제외한다.

| 조건 | 기존 전체 조회 | 변경 후 첫 요약 | 모든 분석 탭 순회 | 캐시 재조회 |
| --- | ---: | ---: | ---: | ---: |
| 오늘·동일 시각 비교·봇 제외 | 38 | 14 | 38 | 0 |
| 최근 7일·이전 기간 비교·봇 제외 | 36 | 12 | 36 | 0 |
| 최근 7일·모바일·출처 미확인 필터·봇 포함 | 36 | 12 | 36 | 0 |

첫 요약의 원본 집계는 약 63~67% 감소하고 모든 탭을 본 경우의 총 집계는 증가하지 않는다. 방문자·세션·현재/이전 추이·모든 차원·흐름·봇 제외·유입 단서의 완성 응답은 기존 전체 조회와 동일하다. 원본 보관 기간 이전은 기존 일별 집계를 사용하며, 없는 화면 유형·흐름·소급 분류를 만들지 않는다.

로컬 H2의 단일 측정에서 전체/요약 조회는 오늘 약 105/24ms, 최근 7일 약 566/51ms였다. 실행 환경·워밍업·데이터 양의 영향을 받는 합성 측정이므로 운영 MySQL의 응답 속도나 개선율로 해석하지 않는다. 운영에서는 완료된 날짜의 지표·탭별 결과를 변경 전후 비교하고 실제 조회 오류와 응답 지연을 확인한다. 대규모 데이터의 운영 DB 실행 계획·부하 수치는 별도 측정이 필요하다.

검증은 `./gradlew test --tests '*analytics*' --no-daemon --max-workers=1`과 `node --test tests/service-analytics-ui.test.mjs tests/analytics-preview-gateway.test.mjs`로 재현한다. 캐시 유효 기간·동시 요청·추가 조회 실패·빠른 탭 이동·늦은 인증 오류·CSV 로딩 잠금도 검사한다. 진행 및 운영 반영 상태는 [상세 통계 최적화 WBS](https://github.com/toilet-project/toilet-admin-api/issues/149)를 따른다.
