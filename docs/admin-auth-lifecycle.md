# 관리자 초기 인증 흐름

## 문제 원인

관리자 HTML이 본문을 표시한 채 내려오고, 페이지별 `/auth/me` 응답이 도착한 뒤에야 본문을 숨기는 구조였다. 느린 요청이나 비로그인 진입에서는 관리자 메뉴·본문 틀이 먼저 보였다.

페이지별 로그인 판정, 상단 세션의 별도 프로필 요청, 레이아웃의 숨김 감시가 각각 화면 상태를 변경했다. 일부 화면은 인증 통신 실패나 업무 데이터 조회 실패를 로그인 만료로 처리했다. 세션 만료는 전체 페이지 새로고침으로 처리해 같은 진입 흐름을 반복했다.

## 변경 책임

- **HTML/CSS:** 최초 상태는 `checking`. 관리자 본문과 메뉴는 숨기고 중립적인 확인 화면을 표시한다.
- **AdminAuth:** 프로필 확인, 관리자 역할 판정, 세션 연장·로그아웃·만료, 인증 화면 표시를 담당한다. 상태는 `checking`, `authenticated`, `anonymous`, `forbidden`, `unavailable`로 구분한다.
- **페이지:** 인증이 확인되면 업무 데이터를 조회한다. 데이터 조회 오류는 해당 화면에서 처리한다.
- **admin-shell:** 레이아웃과 메뉴 이동만 담당한다. 본문의 숨김 상태를 감시해 인증 화면을 제어하지 않는다.
- **admin-session:** 공통 인증 상태를 구독하여 남은 시간과 버튼을 표시한다. 자체 프로필 요청이나 만료 시 페이지 재로딩을 하지 않는다.

동시에 진행되는 인증 요청은 합치고, 화면 이동 전에 이전 요청을 취소한다. 취소를 무시하고 늦게 도착한 응답도 요청 세대와 현재 본문을 확인하여 무시한다. 같은 문서 안에서 메뉴를 이동하면 확인된 세션을 재사용하고, 전체 재진입은 프로필을 다시 조회한다. 만료 시점과 잠자기 후 탭 복귀 시점 모두 만료를 확인한다.

이 변경은 화면 진입 제어다. 서버의 API 인증·권한 검사, 쿠키 속성, OAuth 허용 대상은 바꾸지 않는다. 메뉴 이동에서 재사용한 권한이 서버에서 회수된 경우 서버 API가 접근을 거절한다.

## 검증 및 검수

- 공통 인증과 운영 홈을 실제 코드로 실행하여 인증 대기, 401·403, 권한 부족, 통신 실패, 늦은 응답, 화면 재진입, 요청 중복, 연장 실패, 로그아웃 경쟁, 만료를 검증한다.
- HTML 계약 검사는 모든 관리자 진입점에서 인증 전 본문 숨김과 공통 코드 로딩 순서를 확인한다.
- 기존 제보·개방시간·품질 검토·통계 화면 검사를 함께 실행한다.
- 실데이터 프리뷰: <https://preview.geupddong.com/admin-auth-review/>
- 프리뷰는 운영 데이터 변경을 차단한다. 로그인·연장·로그아웃은 실제 계정 세션을 사용한다. 비로그인 프리뷰의 소셜 로그인은 기존 허용된 관리자 프리뷰로 돌아오므로 로그인 후 위 검수 주소를 다시 열어야 한다.
- 운영 배포는 사용자 검수·별도 승인 후 진행한다. 기존에 열어 둔 운영 탭에는 변경된 코드가 자동 주입되지 않으며 배포 후 새로고침해야 한다.
